# RecompLauncher support

The release profile follows [ADD-SUPPORT.md](https://github.com/elripalda/RecompLauncher/blob/main/docs/ADD-SUPPORT.md), the complete [developer guide](https://github.com/elripalda/RecompLauncher/blob/main/docs/DEVELOPERS.md), [named inputs](https://github.com/elripalda/RecompLauncher/blob/main/docs/SETUP-INPUTS.md), and [Flatpak notes](https://github.com/elripalda/RecompLauncher/blob/main/docs/FLATPAK.md), read on 2026-11-26.

## Setup and play

`recomplauncher.json` identifies `spacefarergames/RedTunic`. Easy Setup asks for the player's supported NUP or extracted game folder, checks build `e0f3ccfa`, then invokes the existing windowless `--cli --prepare` path. The build identifier comes from this project's supported-copy documentation and existing builder validation. No size or CRC32 is asserted: no independently verified dump values were available. The launcher input deliberately excludes `.nx`: the Builder reads that format, but the launcher's documented content check reads NUP and extracted `exefs/main`.

Preparation writes the game to `{data}/game` and intermediate build files to `{data}/cache/build`. Settings remain the existing INI format, at `{data}/game/hookshot_options.ini`; the profile exposes supported menu settings, upscaling, frame generation and output sizes including 720p and 1080p. `saves` names only `{data}/game/user`, never the built game or its assets. Cache folders under the built game are excluded from launcher save backups. The finished-build markers are `image.bin` and `hookshot_version.txt`; missing markers require setup again. The profile does not claim `keeps_copy`, so updates may ask for the original input again.

On Windows, the release zip contains the actual self-contained published app as `RedTunic.exe`, its managed files, runtime and all verified setup-tool parts. It does not start a downloaded bootstrap in AppData. Its opt-in `--play <folder>` starts the built game directly, waits for it to exit, returns its exit code, and disables the game's update question. A `RECOMPLAUNCHER_DATA` path puts the Builder's own files under `{data}/cache/builder`.

On Linux, the profile names an AppImage (rebound by RecompLauncher to the installed image's `AppRun`). `AppRun` already locates its files without `APPIMAGE`; with `RECOMPLAUNCHER_DATA`, it also redirects XDG data, configuration and cache paths. The launch script keeps saves in the selected game folder and continues to drop the Builder's library paths before starting the game. Both the AppImage and tarball contain the same AppDir, with the manifest at its root.

Without the new argument or launcher data environment, normal Builder startup and standalone save behavior are unchanged. Existing compiled shader caches are neither copied into releases nor regenerated by these support changes.

## Packaging and checks

The Windows workflow invokes `scripts/package_recomplauncher.py` after producing the setup list. It reuses `release_parts.py` for checked downloads, verifies local parts too, applies the list's existing destination rules, and refuses incomplete packages, unsafe members and Windows case collisions. It publishes the zip only after all parts are packed. Linux release uploads include the tarball as well as the AppImage; the release completion check requires both portable archives.

Validate the profile against the current JSON schema with a JSON Schema validator. Game-free checks are:

```text
python -I -B tests/test_recomplauncher_json.py
python -I -B tests/test_recomplauncher_package.py
python -I -B tests/test_portable_builder_startup.py
python -I -B tests/test_portable_builder_home.py
python -I -B tests/test_hookshot_launch.py  # Linux
```

The Windows startup check publishes the actual WPF program, then runs its setup and play routes against authored tools and an authored child executable. It checks the renamed apphost, Unicode and spaced paths, data-home precedence, propagated save path, updater suppression, session lifetime, exit status and missing-game errors. No game data is needed. The archive test uses authored local parts and forbids network access. Schema validation uses the upstream schema downloaded for the check, without adding a runtime dependency to the project.

## Standards still to address

- **Encrypted NSP/XCI and explicit player-key paths (large):** the current readers accept decrypted NUP/NX and extracted files. Adding encrypted containers and `--keys` needs readers and title-rights validation; the launcher profile does not pretend these exist or ask for unused keys.
- **Rebuild without the original input (medium):** the Builder has an update route, but Easy Setup does not yet advertise `keeps_copy`; a dedicated, tested fallback must choose that route and validate the retained copy before doing so.
- **Build markers covering the platform executable (medium):** the common completion markers cannot distinguish a manually deleted Windows executable from a deleted Linux one; Play reports a clear setup error. A platform-neutral success marker validated against the complete output would strengthen this.
- **Big Picture defaults and controller glyph handoff (small):** existing SDL controllers and menus work, but the Builder does not yet read `RECOMPLAUNCHER_MODE` or `RECOMPLAUNCHER_PAD`. Mapping them must preserve saved player preferences.
- **Recomp Achievements (large):** no integration currently reports achievements, Beaten/Mastered games or leaderboards; it needs game events and a separately reviewed integration.
- **macOS (large):** there is no supported native Mac build; the current renderer and host require platform work.

The RedTunic repository was not present in the public PC catalog when checked, so the README badge links to the launcher home page. Listing and account ownership remain maintainer actions. The Windows archive passed its bundled dependency check, Python import/probe checks, published startup/play checks and original-icon/version-resource verification. Linux packaging passed unpacked `AppRun --cli --help`, embedded manifest/version checks and seven launch regressions. The full Windows suite has 64 failures that also reproduce in 4.3.0; see the cache-safe validation report. A real RecompLauncher setup UI and the Flatpak sandbox have not been tested, so official launcher certification is not claimed.

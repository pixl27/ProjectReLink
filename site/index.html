03 / ENGINEERING WITH A PAPER TRAIL

Faster texture work.
Measured in context.

Version 5.0.0 cuts CPU work on a measured texture path and improves how the game starts and fits your screen.

Explore the measured runs ↗
01

Decode ASTC textures faster

The optimized CPU path is on by default, with bounded parallel decoding. One reversed-order camera pair cut accumulated CPU upload work from 3.39 s to 0.91 s; mean frame time moved 1.2%. The earlier pair favored serial decode, so this is a loading-work result, not a broad FPS promise.

02

Keep the shaders you built

Version 5.0.0 preserves the translator and cache format. Reuse still depends on matching GPU, toolchain and configuration.

03

Start with Red Tunic

The animated loading screen appears on the integrated-GPU first-use path, with an indeterminate bar and warm fade. A 720p output option fits the title image and scales the complete picture to the window.

04

Choose your distance detail

Lower object detail to 50% to switch distant models sooner. Other mesh-fallback experiments remain optional until separate hardware measurements support a new default.

05 / BEFORE YOU START

The useful
details.

Does this include the game?

No. Red Tunic ships source and build tools. You supply your own supported game, and the native game is built locally.

Is Steam Deck performance verified?

Not yet. Linux and controller-friendly handheld play are development targets. Published measurements identify the actual Radeon Vega reference PC; they should not be read as Deck results.

Will an update erase my shaders or saves?

Keep your existing output folder when updating a standalone build. The 5.0.0 changes preserve the shader translator and cache format, but cache compatibility still depends on GPU, toolchain and configuration. RecompLauncher keeps its separate data under recompdata.

Is this an official Nintendo project?

No. Red Tunic is an independent, unofficial project based on Hookshot. Nintendo, AMD, Valve and IGN retain their respective trademarks and media rights.
